# New unbilled test project

Use this route when creating a new test project is already authorized and the intended human Google login is saved in the original gcloud configuration. This is a fresh connector identity using an existing Google login, not a fresh Google signup. Reuse the selected account; never switch to a more privileged or unrelated login merely because it is available.

From this skill's directory, run Python 3 with `scripts/connect.py new-project --account <intended-human-email> --project <fresh-project-id> --name <test-name>`. Select a globally unique project ID conforming to Google's 6–30 character rules. The helper does not set it as default. Its optional top-level `--directory` changes the connector destination; the default is `~/.config/gcloud-connector`.

The helper records the original configuration path, active account/project/configuration, file hashes, and whether authentication or endpoint overrides are present. Overrides stop setup for review without exposing their values. Provisioning uses the original credential store with explicit `--account`, `--project`, and `--configuration` on every request. An empty isolated credential store cannot reuse the human login.

Only these new resources are provisioned: the unbilled project, IAM API enablement, `claude-assistant` service account, its project Viewer binding, and one key. IAM is offered at no additional charge; this route does not link billing, deploy resources, or enable product APIs. Project creation permissions, organization policies, and quotas still apply. [Project creation](https://docs.cloud.google.com/resource-manager/docs/creating-managing-projects), [IAM pricing](https://cloud.google.com/iam/pricing), and [create command flags](https://docs.cloud.google.com/sdk/gcloud/reference/projects/create).

The new mode-700 directory is reserved atomically and existing paths are refused. Google’s key command can truncate its destination during validation, so the helper uses only a nonexistent filename inside that new private directory. Never point it at an existing key. All output is captured; key identity and presence checks stay private. The mode-600 key is activated only in the new `cli/` directory through process-local `CLOUDSDK_CONFIG`; the original configuration is checked again after setup. [Configuration isolation](https://docs.cloud.google.com/sdk/docs/configurations), [key creation and organization restrictions](https://docs.cloud.google.com/iam/docs/keys-create-delete).

`credentials.env` records the isolated CLI path, exact service account/project, and ADC key path after a successful project read. Source it inside each operation's subshell. `connection.json` records connector ownership. `original.json` and stage markers support partial-setup diagnosis without credentials in output.

On failure, preserve the directory, project, account, roles, and keys. The most recent `.started` without `.complete` identifies the uncertain operation. Inspect its exact remote state with the original human login and explicit project flags; do not automatically repeat it. A failed key creation may leave an empty file, or a remote key may exist despite a timeout. Organization policy or key limits require review, not key deletion, policy changes, broader roles, or billing changes. Rerunning `new-project` deliberately refuses partial state; use a reviewed repair of the owned resources instead of creating duplicates.

Run `python3 scripts/connect.py check` after success from the actual caller. It checks both the original context and the saved isolated configuration for authentication and endpoint overrides before the authenticated read: an override can supersede `--account` even when the displayed account looks correct. Preserve an unexpected override for review rather than clearing it automatically. The response must confirm the saved account/project and real authenticated project read. The Viewer test proves read access to this project only. Additional cloud operations retain their ordinary permission and billing requirements.

Failed CLI requests report only a fixed operation name and an allowlisted category, such as `KEY_CREATE_ORG_POLICY`, `IAM_API_ENABLE_SERVICE_DISABLED`, or `PROJECT_CREATE_PERMISSION`. Translate that category for the attendee and use the saved stage markers to target diagnosis. Raw stdout/stderr and credential values are not returned or logged. `UNCLASSIFIED` means the captured error did not match a known category; do not infer a cause or change policy from it.
